# 多轮运行崩溃修复（3.1.0）

## 复现依据

用户 Windows 10 的 3.0.0 EXE 报告：`shiboken6.abi3.dll`，`0xc0000005`，偏移
`0x26f20`。本机 Windows 11 的原始 3.0.0 代码使用真实 MonitorController / QThread /
SwitchEngine 连续处理模拟节点，在约几十轮后复现相同模块、异常码和偏移。
faulthandler 栈多次落在 `_result` 的 `table.setRowCount(0)`，属于原生崩溃，
不是网络异常暂停或一小时退出定时器。

原生跨语言调用存在对象生命周期问题，但没有完整 C++ 内存 dump，不能据此断言
所有 Shiboken 崩溃都出于同一根因。仅替换完成回调、限制自动 GC 或对照 Qt 6.8.3
均不足以通过相同场景，最终保留已验证的 6.10.3，不以依赖降级掩盖问题。

## 修复与诊断

- 节点表和总览不再每轮清空并重建所有 item，改为原地更新；节点增减才调整行数。
  旧高亮、错误提示、状态颜色同步清理，保持搜索、选择、滚动与长节点提示。
- 工作任务结果、失败、完成在主线程排队处理；结束后释放 task 闭包并延迟删除线程。
- `logs/runtime-status.json` 每分钟更新本次版本、运行时版本、存活时间、内存/线程/
  句柄及自动运行/忙碌状态。正常退出后写入 clean_exit；缺少标记仅说明非正常退出，
  不单凭它判断崩溃（断电/任务管理器终止也会留下该状态）。
- `logs/native-crash.log` 捕获 Python 可捕获的原生故障栈，下一次运行保留一份
  `native-crash.previous.log`。不捕获完整内存或局部变量，不写密钥和节点信息。
- 未处理 Python 异常只记录类型和调用位置，不写异常值/源代码。诊断失败不弹窗。
- Windows 强制结束、安全软件终止、部分原生故障可能无法写出栈，仍需事件查看器佐证。

## 验证

复现记录和压力样本保留在忽略的本机 `verification/soak-*` 目录，不操作真实节点。
原始版本两次失败，显式 queued slot 对照和手动 GC 对照仍失败。单元格复用后首轮
300 次（23.81 秒）通过；随后 3000 轮变更节点数量测试通过（239.67 秒），
没有 Python 异常或控制器错误，正常退出，真实网络请求为零。采样工作线程均已清理，
动画通道保持 35；RSS 约 276 MB 起、峰值约 284 MB、结束约 228 MB。
句柄由约 1793 增至 1902，后段在约 1900 附近，未出现逐轮无界增长。
该 3000 轮使用修复代码，启动时尚未更新应用版本，诊断版本仍记录为 3.0.0。

本地修复阶段（临时版本号 3.0.1），Windows 原生 Qt 完整回归 146 项通过（33.40 秒），覆盖设置编辑、
重连恢复、后台无弹窗、表格复用、线程清理、诊断隐私和独立进程连续运行。
最终 3.1.0 原生 Qt 完整回归 146 项通过（34.32 秒），offscreen 完整回归 146 项
通过（22.27 秒）。依赖检查、编译检查及 diff 检查通过。
最终 3.1.0 再次执行 3000 轮（235.58 秒）通过，无 Python 异常或控制器错误，
正常退出。采样工作线程均清理，动画通道固定 38，末次 RSS 228.22 MB、句柄 1881；
记录位于 `verification/soak-v310-final`，运行诊断版本为 3.1.0。
Windows x64 EXE 已重新构建，PE 文件/产品版本均为 3.1.0；独立配置启动正常退出，
诊断版本 3.1.0、clean_exit 为 true，截图检查字体与图标正常。
便携 ZIP 完整性、资源允许列表及独立配置打包冒烟通过。
尚未完成 Windows 10 或超过一小时的实机运行。

运行加速验证：

```powershell
python scripts/soak_ui.py --rounds 3000 --vary-members --output-dir verification/soak-local
```


最低持续时长与轮次必须同时满足。每轮有真实 QThread、并发测速和 UI 更新，定期
隐藏/显示并进行主线程垃圾回收。测试使用独立配置，报告内存/句柄/线程/任务清理。
加速轮次不能替代用户 Windows 10 的一小时实机验收；没有完成的检查不会报告通过。
